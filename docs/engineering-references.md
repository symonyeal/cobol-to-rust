# Engineering references

These course revisions are pinned for design context. The COBOL course discusses Enterprise COBOL and z/OS. It is useful for language structure, data declarations, and testing vocabulary, but it does not establish GnuCOBOL runtime behavior. The runtime-specific decisions below rely on the admitted source, the pinned GnuCOBOL 3.2 profile, and executable captures.

## Applying the references

| Source concept | Workbench decision | Evidence and executable check |
| --- | --- | --- |
| COBOL separates declarations from work; paragraphs, statements, and scope terminators control execution. | Keep the command-line shell in [`main.rs`](../src/main.rs), baseline/case orchestration in [`workbench.rs`](../src/workbench.rs), raw process observation in [`capture.rs`](../src/capture.rs), and individual ports in their own modules. The formatter driver calls the source subprogram over the full valid input range in both directions. | [`drivers/formatter.cob`](../drivers/formatter.cob); [`tests/workbench.rs`](../tests/workbench.rs) checks case validation and rejection of unsafe paths. |
| `PIC` declares a field's length and category; COBOL numeric storage encodings vary by `USAGE` and compiler. | Treat the sales source's line-sequential file as byte fields with explicit offsets, then implement the observed numeric and edit rules directly in [`sales.rs`](../src/sales.rs). The source declares a 60-byte record, `PIC 9(3)` quantity, `PIC 999V99` cost, and `PIC X(71)` report record. Do not infer GnuCOBOL's bytes from IBM packed/zoned/binary examples. | [Pinned sales source, declarations](https://github.com/tylerbro93/COBOL-SALES-INVENTORY-REPORT-DEMONSTRATION/blob/ece4ed7efcbcc9a232318956cf9765d036a5b18f/project2.cbl#L59-L90); [`tests/sales.rs`](../tests/sales.rs) covers byte layout, short-record padding, decimal display, and PIC destination truncation. GnuCOBOL evidence is in [`reference-profile.md`](reference-profile.md) and the local baseline captures, not the Enterprise-oriented course. |
| `PERFORM` and explicit terminators express record loops and conditional branches. | Preserve the sales program's initial paragraph sequence, `PERFORM UNTIL`/`READ`/`END-READ` control flow, grouping transition, and totals behavior as named steps in the port. Keep input reading in `run`; keep the byte transformation in `report`. | [Pinned sales source, main/read/grouping flow](https://github.com/tylerbro93/COBOL-SALES-INVENTORY-REPORT-DEMONSTRATION/blob/ece4ed7efcbcc9a232318956cf9765d036a5b18f/project2.cbl#L167-L256); [`tests/sales.rs`](../tests/sales.rs) checks group-state and repeated-name behavior. The case manifest declares empty, duplicate-group, boundary, and partial-record scenarios in [`sales.json`](../cases/sales.json). |
| Report advancement and the date input operation are source-level behavior. | Preserve `WRITE ... AFTER ADVANCING` and `ADVANCING PAGE` as output bytes/page transitions; preserve `ACCEPT WS-DATE FROM DATE` as a six-digit `YYMMDD` source. The port's `date_from_environment` reads the same date override used by the pinned runtime. It must not replace this operation with `FUNCTION CURRENT-DATE`. | [Pinned sales source, `ACCEPT FROM DATE`](https://github.com/tylerbro93/COBOL-SALES-INVENTORY-REPORT-DEMONSTRATION/blob/ece4ed7efcbcc9a232318956cf9765d036a5b18f/project2.cbl#L182-L187) and [report/page writes](https://github.com/tylerbro93/COBOL-SALES-INVENTORY-REPORT-DEMONSTRATION/blob/ece4ed7efcbcc9a232318956cf9765d036a5b18f/project2.cbl#L189-L204), [record threshold and page routine](https://github.com/tylerbro93/COBOL-SALES-INVENTORY-REPORT-DEMONSTRATION/blob/ece4ed7efcbcc9a232318956cf9765d036a5b18f/project2.cbl#L206-L223). The sales scenarios straddle the 44/45/46-record boundary; the unit test checks form-feed placement. Provisioning smoke verifies `ACCEPT ... FROM DATE` gives `261106` for the fixed profile date. The same smoke shows `FUNCTION CURRENT-DATE` retains variable fractional digits even with `COB_CURRENT_DATE`; see [`reference-profile.md`](reference-profile.md). |
| Rust ownership and slices let the port consume borrowed record bytes while retaining owned outputs and captures. | [`sales::report`](../src/sales.rs) reads `&[u8]` and returns owned report bytes; [`capture.rs`](../src/capture.rs) stores owned stdout, stderr, and before/after file bytes so the child can exit without invalidating the observation. | [`tests/capture.rs`](../tests/capture.rs) exercises binary output, large streams, file snapshots, status, timeout, and byte-level mutations. |
| `Result` separates expected processing output from infrastructure and invalid-input errors; modules keep related decisions together. | `sales::report` returns an error for invalid numeric bytes or overflow. `main` routes commands; the capture, inventory, workbench, formatter, and sales modules own separate concerns. | [`sales.rs`](../src/sales.rs), [`main.rs`](../src/main.rs), [`workbench.rs`](../src/workbench.rs); [`tests/workbench.rs`](../tests/workbench.rs) checks malformed manifests and unsafe paths. |
| Automated tests make the expected behavior repeatable and allow defects to be detected. | First validate the capture comparator with deliberate defects; then use repeated reference captures and declared sales scenarios for byte-exact acceptance. ## Compiler-specific boundary

The course's numeric representation chapter discusses zoned and packed decimal and describes binary formats in IBM mainframe terms. The course's testing material likewise covers z/OS. Those sections help identify questions but do not answer how this GnuCOBOL build stores, edits, rounds, advances, or reports dates. For this work, the authoritative runtime evidence is the pinned [GnuCOBOL 3.2 profile](reference-profile.md), the exact admitted [`project2.cbl`](https://github.com/tylerbro93/COBOL-SALES-INVENTORY-REPORT-DEMONSTRATION/blob/ece4ed7efcbcc9a232318956cf9765d036a5b18f/project2.cbl), and retained executions of that source against the declared cases.
